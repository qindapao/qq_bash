性能优化 backlog（2026-11-17 整理，按执行顺序）

基线：111 发敌弹的 Boss 战，30 行终端
    _play_game_tick ≈ 28.9 ms  （段 5 move ≈ 17.2，伤害判定 ≈ 8.6，其余 ≈ 3.1）
    render          ≈ 16–20 ms （擦除 ≈ 6.5，绘制 ≈ 9.5，玩家 ≈ 1，flush ≈ 0.2）
    合计 ≈ 45–50 ms/帧，30fps 预算 33.3 ms
原则：只能变好不能变差；每步都量；验收用帧哈希或屏幕比对器。

[P0] 帧缓冲（render 16ms → 目标 ~2ms）—— 最大的一块，建议整块时间做
  现状：111 发敌弹即使静止，每帧也要"擦一次 + 画一次"（约 222 次写入），
        而真正变化的格子只有 ~30 个 → 约 85% 是重复劳动。
  设计：
    CELL[(y-1)*W+x] = "颜色+字符"   屏幕真值
    DIRTY[]         = 本帧变过的格  只 emit 这些
    关键：写格子必须在 <cls>_move 内部（self 已绑、x/y 刚算出来）。
          在 tick 的 move 循环里写不行——为拿坐标要再绑一次 nameref，
          省下的正好被吃掉（已实测推演）。
  前置（已完成）：数组只含活句柄（子弹打导弹改为"先标记后清理"）。
  步骤：
    1. CELL/DIRTY/emit 核心 + 屏幕比对器
       （bash 把一帧的 escape 流跑成网格，比较新旧渲染器最终画面；
         输出顺序会变，md5 帧哈希不再适用）
    2. 迁移 EnemyBullet（111 发，最大头）
    3. 迁移其余单格对象：Bullet/BossBullet/EnemyMissile/Missile/Drop/Word
    4. 迁移敌人多行 art（_scene_art_lines / _scene_clear_art_at）
    5. HUD / 电网 / 特效 / 玩家
  风险：层叠顺序（现在 art 画在子弹之后、盖住它们）；一次性绘制（横幅/清屏）。
  验收：屏幕比对器逐格一致 + 每步量 render 耗时。

[P1] tick 伤害判定并入移动循环（~5ms，中等风险）
  现状：敌弹每 tick 遍历两遍——段 5 移动（~80µs/发）、段 9 伤害判定（~75µs/发）。
  做法：合并成一遍，省一次 nameref 绑定 + 2 次坐标读。
  风险：伤害必须在"所有子弹移动完之后"结算（护盾/无敌帧的时序）；
        循环里 _enemy_bullet_bury 会改数组。
  验收：帧哈希一致 + 定向用例（同 tick 多发命中 / 护盾 / 无敌帧 / 贴脸）。

x.in
    * 性能优化
        *. 从 children 数组中找 token 的数字索引不需要先把它转换成数组然后再找，可以考虑使用类似下面
            这种方法，效率非常高
            https://github.com/akinomyoga/ble.sh/blob/master/src/util.sh
            ## @fn ble/string#last-index-of text needle [n]
            ##   @param[in] text
            ##   @param[in] needle
            ##   @param[in] n
            ##     この引数を指定したとき n 番目の一致を検索します。
            ##   @var[out] ret
            function ble/string#last-index-of {
              local haystack=$1 needle=$2 count=${3:-1}
              ble/string#repeat '"$needle"*' "$count"; local pattern=$ret
              builtin eval "local transformed=\${haystack%$pattern}"
              if [[ $transformed == "$haystack" ]]; then
                ret=-1
              else
                ret=${#transformed}
              fi
              ((ret>=0))
            }
            当前由于token是Q字符串，所以如果夹带了索引，要一起寻找匹配Q字符串+ID。
    * 边缘BUG排查
        * 脏键/丢键审计（灾备预案）：
            目前未发现异常，暂不实现。未来出现玄学问题（如内存泄漏、找不到节点）时启用。

            【实现方式】独立封装为 x_verify_tree 函数，严禁修改 x_walk 本身！
            函数内调用 x_walk 做一次从根节点的全量遍历，同时统计访问到的有效 KV 数量。

            【计数规则（极易写错，必须对称）】
            遍历回调中，对每个节点精确累加：
                节点自身的存在感     +1
                节点 .t (类型)      +1 (若有)
                节点 .k (物理路径)   +1 (若有，叶子)
                节点 .s (子节点列表) +1 (若有，容器)
                节点 .c.{key} 映射  +1 (遍历 .s 里的对象键，每个算 1)
            遍历结束后，手动补上未被 x_walk 遍历到的内部键：
                根节点的 .t         +1
                max_index           +1

            【比对逻辑】
            若 统计总数 != ${#tree[@]} ，说明存在“幽灵键”或“孤儿映射”，直接 die 报错。

            【调用时机（信任点主动调用，严禁进热路径）】
            1. 游戏存档 (save_game) 之前 / 读档重建之后。
            2. 测试用例 (test.sh) 的收尾阶段。
            3. x_init 初始化一个复杂的类对象之后。
